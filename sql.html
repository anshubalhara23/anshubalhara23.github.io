OlistEcom — End-to-End Data Warehouse

A production-quality data warehouse built on SQL Server for the Olist Brazilian e-commerce dataset, using a Bronze/Silver/Gold medallion architecture. Raw, inconsistent order and customer data is cleaned, validated, and modeled into a star schema that powers a 17-question Power BI dashboard.

SQL Server T-SQL Medallion Architecture Star Schema Stored Procedures

The Olist dataset arrives as several relational CSVs with real-world data quality problems: impossible order states, timestamps that occur out of sequence, missing product metadata, and heavily duplicated geolocation records. This project builds a repeatable pipeline that takes that raw data and turns it into a clean, query-ready warehouse.

Bronze layer: raw data loaded as-is from source CSVs.

Silver layer: cleaned and validated data, including:

  • Removed 14 logically impossible "delivered" orders
  • Nulled order_approved_at for ~1,359 rows where carrier pickup preceded approval
  • Nulled order_delivered_customer_date for 23 rows with reversed date sequencing
  • Defaulted 610 products with missing metadata to safe fallback values
  • Collapsed ~128,174 duplicate geolocation rows using DISTINCT
  • Preserved legitimate NULL timestamps on orders that were genuinely not yet delivered

Gold layer: a star schema exposed as views — 4 dimension tables (customers, products, sellers, geolocation) and 3 fact tables (orders, order items, payments). The seller-to-geolocation relationship was deliberately removed to break a relationship cycle, and all fact table joins use LEFT JOIN to avoid dropping valid rows. fact_orders resolves duplicate review records using a ROW_NUMBER() CTE.

Built entirely in SQL Server. The Silver layer load is orchestrated through a stored procedure, silver.load_silver, wrapped in TRY/CATCH blocks for error handling. Gold-layer objects are implemented as views rather than physical tables to keep the warehouse always in sync with Silver, and dim_date is intentionally excluded since Power BI generates the date table directly using DAX's CALENDAR() function.
